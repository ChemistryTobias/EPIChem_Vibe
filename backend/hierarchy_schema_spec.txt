CONCEPTUAL SHAPE (current model, ADR 0007 + refinements)

  Site
    Lab                    -- physical room, own isometric floor grid
      Zone (optional)      -- 2D area, EITHER lab-scoped OR site-scoped, not both
        Station             -- group of >=1 device, placed on lab grid
          Device (leaf, or "module" if node_kind="module", self-nesting via parent_id)
            Signal          -- device's readable/writable channels (ophyd, M2 future)

  CapabilityClass  -- referenced by Device.capability_class_id, no parent/child ties
  Revision         -- one polymorphic history table over every entity below

  Notes on the shape:
  - Station's parent is ALWAYS a Lab. Zone is an OPTIONAL second parent
    (Station.zone_id nullable) -- Zone and Station are siblings under Lab.
  - "Module" is NOT a separate table -- it's a Device row with node_kind="module",
    nested under a parent Device via self-referencing parent_id.
  - Zone.lab_id / Zone.site_id: exactly one is set (site-scoped OR lab-scoped zone).


--------------------------------------------------------------------------------
SHARED BASE FIELDS (every "RegistryEntity" table below repeats this shape)
--------------------------------------------------------------------------------
  id            UUID        PK, default=uuid7()   [time-sortable UUID, not UUID4]
  code          str         NOT NULL, UNIQUE, indexed   [short human ID, e.g. "DEV-HP-002"]
  name          str         NOT NULL
  created_at    datetime(tz) server_default=now()
  updated_at    datetime(tz) server_default=now(), onupdate=now()

  RegistryEntity tables: Site, Lab, Zone, Station, Device, Sample.
  NOT RegistryEntity (different id/name shape): CapabilityClass, Signal, Revision.


================================================================================
Site
================================================================================
table: sites

FIELDS (beyond shared base)
  address       str | None    nullable
  timezone      str | None    nullable
  width_m       float         NOT NULL, default 40.0   -- own site canvas (ADR 0012)
  depth_m       float         NOT NULL, default 40.0
  grid_size_m   float         NOT NULL, default 1.0
  floors        int           NOT NULL, default 1       -- layout-only storeys (ADR 0013)

FOREIGN KEYS: none

RELATIONSHIPS
  labs  -> Lab   one-to-many   (site.labs)
  zones -> Zone  one-to-many   (site.zones, site-scoped zones only)

no `virtual` flag on Site.


================================================================================
Lab
================================================================================
table: labs

FIELDS (beyond shared base)
  site_id                UUID        NOT NULL  -> FK sites.id
  room_number            str | None  nullable
  environment_class      str         NOT NULL, default "ambient"
                          [allowed: ambient | glovebox | fume_hood | cleanroom]
  access_control_group   str | None  nullable
  width_m                float       NOT NULL, default 6.0   -- own floor canvas (ADR 0010)
  depth_m                float       NOT NULL, default 4.0
  grid_size_m            float       NOT NULL, default 0.5
  site_pos_x             float       NOT NULL, default 0.0   -- box on Site canvas (ADR 0012)
  site_pos_y             float       NOT NULL, default 0.0
  site_size_x_m          float       NOT NULL, default 10.0
  site_size_y_m          float       NOT NULL, default 10.0
  floor                  int         NOT NULL, default 0     -- which site storey (ADR 0013)

FOREIGN KEYS
  site_id -> sites.id

RELATIONSHIPS
  site     -> Site      many-to-one
  zones    -> Zone       one-to-many   (lab-scoped zones)
  stations -> Station    one-to-many

no `virtual` flag on Lab.


================================================================================
Zone
================================================================================
table: zones

FIELDS (beyond shared base)
  lab_id              UUID | None  nullable -> FK labs.id
  site_id             UUID | None  nullable -> FK sites.id
                       [exactly one of lab_id/site_id set -- enforce however you like,
                        old backend only enforced this in Pydantic, not the DB]
  pos_x               float   NOT NULL, default 0.0     -- 2D rectangle (ADR 0015)
  pos_y               float   NOT NULL, default 0.0
  width_m             float   NOT NULL, default 0.0     -- 0x0 = classification-only, no drawn area
  depth_m             float   NOT NULL, default 0.0
  purpose             str     NOT NULL, default "area"   [free string, e.g. walkable/keep-out]
  atmosphere          str     NOT NULL, default "air"     [allowed: air | n2 | ar]
  pressure            str | None  nullable
  temperature_class   str | None  nullable
  hazard_class        str | None  nullable
  occupancy           str     NOT NULL, default "shared"  [allowed: human | robot | shared]

FOREIGN KEYS
  lab_id  -> labs.id   (nullable)
  site_id -> sites.id  (nullable)

RELATIONSHIPS
  lab      -> Lab | None    many-to-one
  site     -> Site | None   many-to-one
  stations -> Station       one-to-many

no `virtual` flag on Zone.
Old backend also kept Station.zone_id as a real FK alongside geometric containment --
decide whether you want stored membership, computed-on-read membership, or both.

Station
================================================================================
table: stations

FIELDS (beyond shared base)
  lab_id                     UUID        NOT NULL -> FK labs.id
  zone_id                    UUID | None nullable -> FK zones.id
  kind                       str         NOT NULL, default "generic"   [free string]
  pos_x                      float       NOT NULL, default 0.0   -- box on Lab canvas (ADR 0010)
  pos_y                      float       NOT NULL, default 0.0
  size_x_m                   float       NOT NULL, default 1.0
  size_y_m                   float       NOT NULL, default 1.0
  height_m                   float       NOT NULL, default 0.5
  capacity                   int         NOT NULL, default 1

  queueserver_endpoint       str | None  nullable   -- execution binding
  redis_namespace            str | None  nullable   -- execution binding
  state                      str         NOT NULL, default "active"
                             [allowed: active | maintenance | offline]
  owning_group               str | None  nullable
  virtual                    bool        NOT NULL, default False   -- soft-hide (ADR 0011)

FOREIGN KEYS
  lab_id  -> labs.id   (NOT NULL)
  zone_id -> zones.id  (nullable)

RELATIONSHIPS
  lab     -> Lab               many-to-one
  zone    -> Zone | None       many-to-one
  devices -> Device             one-to-many
             [old backend: NO cascade -- deleting a station with devices raises
              IntegrityError/409; devices must be reassigned or deleted first]

Device   (also represents "Module" via node_kind discriminator)
================================================================================
table: devices

One table for both the controllable leaf (node_kind="device") and a recursive
grouping/passive node (node_kind="module", no driver), nested via self-FK parent_id.

FIELDS (beyond shared base)
  node_kind                        str          NOT NULL, default "device"
                                    [allowed: device | module]
  station_id                       UUID | None  nullable -> FK stations.id
  parent_id                        UUID | None  nullable -> FK devices.id (self)
  labels                           dict         JSON, NOT NULL, default {}
  capability_class_ref             str | None   nullable   -- raw dotted ref string
  capability_class_id              UUID | None  nullable -> FK capability_classes.id
  capabilities                     list[str]    JSON, NOT NULL, default []
  ophyd_import                     str | None   nullable
  ophyd_args                       dict         JSON, NOT NULL, default {}
  transport_protocol               str | None   nullable
                                    [allowed: epics-ca | epics-pva | tango | rest | sila2 | opcua | sim]
  transport_uri                    str | None   nullable
  transport_ioc_host               str | None   nullable
  transport_quality                str          NOT NULL, default "nominal"
                                    [allowed: nominal | degraded]
  network_netbox_device_id         int | None   nullable
  network_primary_ip               str | None   nullable
  network_mac                      str | None   nullable
  network_vlan                     str | None   nullable
  pose_x_mm                        float | None nullable
  pose_y_mm                        float | None nullable
  pose_z_mm                        float | None nullable
  pose_yaw_deg                     float | None nullable
  size_x_mm                        float | None nullable   -- footprint (ADR 0012)
  size_y_mm                        float | None nullable
  size_z_mm                        float | None nullable
  envelope                         dict         JSON, NOT NULL, default {}
  safety_flags                     list[str]    JSON, NOT NULL, default []
  safety_interlocks                list[str]    JSON, NOT NULL, default []
  safety_max_unattended_minutes    int | None   nullable
  operational_mode                 str          NOT NULL, default "read_write"
                                    [allowed: read_only | read_write | maintenance | disabled]
  operational_calibration          dict | None  JSON, nullable
  virtual                          bool         NOT NULL, default False   -- soft-hide (ADR 0011)

FOREIGN KEYS
  station_id           -> stations.id            (nullable)
  parent_id            -> devices.id (self)      (nullable)
  capability_class_id  -> capability_classes.id  (nullable)

RELATIONSHIPS
  children -> Device        one-to-many (self)
  parent   -> Device | None many-to-one (self)
  station  -> Station | None many-to-one
  signals  -> Signal          one-to-many
              [old backend: cascade="all, delete-orphan" -- signals have no
               independent existence, deleting a device deletes its signals]
  (capability_class_id was a plain FK column, no ORM relationship() to
  CapabilityClass in the old backend -- add one if convenient)


================================================================================
Signal
================================================================================
table: signals
NOT RegistryEntity -- own id/created_at/updated_at, no code/name pair.
Populated by ophyd introspection (future M2 work) -- currently unwritten in practice.

FIELDS
  id            UUID          PK, default=uuid7()
  created_at    datetime(tz)  server_default=now()
  updated_at    datetime(tz)  server_default=now(), onupdate=now()
  device_id     UUID          NOT NULL -> FK devices.id
  name          str           NOT NULL   -- PV/attribute name, not a human label
  dtype         str | None    nullable
  units         str | None    nullable
  limits        dict | None   JSON, nullable
  precision     float | None  nullable
  kind          str           NOT NULL, default "normal"
                [allowed, comment-only in old code: primary | config | normal | omitted]

FOREIGN KEYS
  device_id -> devices.id

RELATIONSHIPS
  device -> Device   many-to-one

UNIQUE CONSTRAINT (multi-column)
  (device_id, name) unique together -- a device can't have two signals with the same name.


================================================================================
CapabilityClass
================================================================================
table: capability_classes
NOT RegistryEntity -- has `name` only (no separate `code`), unique.
Represents the interface a device promises, decoupled from vendor.

FIELDS
  id            UUID          PK, default=uuid7()
  created_at    datetime(tz)  server_default=now()
  updated_at    datetime(tz)  server_default=now(), onupdate=now()
  name          str           NOT NULL, UNIQUE, indexed   -- e.g. "HeaterStirrer"
  iri           str | None    nullable   -- ontology IRI
  extends       list[str]     JSON, NOT NULL, default []   -- parent capability class names
  actions       dict          JSON, NOT NULL, default {}   -- RFC2119 action contract

FOREIGN KEYS: none
RELATIONSHIPS: none defined (Device.capability_class_id points here as a plain FK)


================================================================================
Revision
================================================================================
table: revisions
NOT RegistryEntity -- no updated_at (a revision row is immutable once written).
One kind-agnostic table recording full-snapshot history for every entity above
(and Sample). Full JSON snapshot per write, not a diff/patch log.

FIELDS
  id                UUID          PK, default=uuid7()
  entity_type       str           NOT NULL   -- e.g. "site" | "lab" | "device" | ...
  entity_id         UUID          NOT NULL   -- points into whichever table entity_type names
                                  [NOT a real FK -- can reference any of several tables]
  revision_number   int           NOT NULL
  action            str           NOT NULL   [allowed, comment-only: created | updated | deleted]
  snapshot          dict          JSON, NOT NULL   -- full entity snapshot
  created_at        datetime(tz)  server_default=now()
  created_by        str | None    nullable   -- no auth/identity existed yet

FOREIGN KEYS: none (entity_id/entity_type is a polymorphic pseudo-FK)

UNIQUE CONSTRAINT (multi-column)
  (entity_type, entity_id, revision_number) unique together

INDEX
  (entity_type, entity_id)

  location       str | None   nullable   -- free text, e.g. "RACK-A/3", NOT a topology FK

  notes          str | None   nullable

FOREIGN KEYS: none


================================================================================
CROSS-CUTTING NOTES FROM THE OLD BACKEND (keep, drop, or change as you like)
================================================================================
1. PKs were UUIDv7 (time-sortable), not UUID4 or int.
2. No DB-level enums or CHECK constraints anywhere -- every "[allowed: ...]"
   list above was enforced only at the Pydantic layer, not the database.
   Stated reason: "the allowed value sets are still evolving and a schema
   migration per new value would be friction."
3. `virtual` (soft-hide bool) existed ONLY on Station and Device -- deliberately
   not on Site/Lab/Zone.
4. Cascade behavior was explicit and asymmetric:
   - Device -> Signal: hard cascade delete (signals die with their device)
   - Station -> Device: NO cascade (blocked by IntegrityError/409 if devices exist)
   - everything else: no cascade specified, default SQLAlchemy behavior
5. Zone membership: old backend computed it geometrically on read (rectangle
   full-containment) for display, but ALSO persisted Station.zone_id and
   reconciled it to match the drawing on layout-editor Save. Decide if you
   want both, or pick one.
6. Geometry fields are all "snap-but-not-bound": placement is validated softly
   (UI warning) but nothing in the DB enforces boxes staying on their canvas
   or off each other.
